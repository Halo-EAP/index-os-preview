IndeXOS

A phone OS where the whole interface is a theme. Apply one and the lock screen, home screen, settings and dock all change together — as a phone, a desktop, or a tablet.

What IndeXOS is

A Linux-based operating system for phones, built around one idea: the interface should not be fixed. A .hui theme file describes the entire look — status bar, clock, icon grid, dock, navigation, notification shade, app switcher, settings layout, animations — and the shell draws the system from it. Themes are interchangeable and take effect on restart.

The same phone can also present a different interface per device mode. Attach a dock and it becomes a desktop with a taskbar, window frames and a start menu; attach a tablet shell and it becomes a tablet with a dock and split view. The theme decides how each of those looks.

What is working today

  • ✓The profile format and its loader. One .hui file describes the whole UI. Every value is validated and clamped, a corrupt or hostile file is refused, and a theme that fails to load rolls back to the previous one automatically instead of leaving a blank screen. This part has a test suite and passes it.
  • ✓Desktop and tablet looks as data. The format defines separate element sets for a desktop shell (top bar, taskbar, window chrome, start menu, desktop icons) and a tablet shell (status bar, dock, grid, split view), so a theme can style all three modes without code.
  • ✓The Designer. A Windows desktop app that renders the phone, desktop and tablet shells live while you edit, and saves the result as a .hui. Pre-alpha.
  • ✓The shell itself. A native Qt/QML shell loads an installed theme and draws the phone, desktop or tablet surface from it. It is clickable: app icons open windows, the desktop has a working start menu, and the surface can be switched at runtime. It runs as a window on a PC today; the same QML is what will run on the phone.
  • ✓Dock detection. On Linux the shell reads attached USB devices and displays, recognises a CoolDock, laptop dock or tablet shell, and records which surface to draw. The choice is tested; only the physical docks are missing.

Not built yet: the bootable OS image, the app runtimes (Windows and Android), the theme Workshop and community store, third-party app theming, and the hardware. Those are why there is nothing to install on a phone today.

Next up

  • First device build — package the shell for a supported phone and boot it, then test the runtime hand-offs for Windows and Android apps.
  • Third-party app theming — the opt-in API and adapters so apps that are not ours still follow the active theme.
  • The Workshop — install, switch and roll back themes from one app, plus the store that lets people publish them.

Hardware direction

Concept · nothing built

Custom Back Glass

Rear glass intended for active thermal dissipation and a distinct visual identity.

CoolDock

An active cooling dock with heatsink and fans, plus a USB hub for desktop work: two USB-C, two USB-A, HDMI, DisplayPort and Ethernet.

Halet

The portable companion shell — a larger screen that the phone slots into, with its own battery and headphone jack.

TV Dock

Display output for a large screen, with multi-window scaling.

Distribution

A closed, native ecosystem

IndeXOS is not planned to ship as an open-source image, a generic custom ROM, or a public installer for third-party smartphones. The profile format and the Designer are shared so themes can be made and tested; the OS, the hardware and the emulation stack stay internal.

Roadmap

  • Phase 1 · Software core — in progress: profile format, loader, storage with rollback, the three-surface shell, and dock detection. The shell already runs on a PC; the phone build is next.
  • Phase 2 · Physical board testing — flashing validated builds onto prototype boards.
  • Phase 3 · Tooling and manufacturing — enclosures, thermal glass, and only then any talk of pre-orders.

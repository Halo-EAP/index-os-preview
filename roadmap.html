Roadmap

Where the work stands.

Three phases. The first is partly built and tested, the other two have not started. No dates are published, because a date here would be a guess dressed up as a plan.

Phase 1 of 3 · in progress

Phase 1 · Software core

A shell that draws itself from a theme

In progress

The format, the loader, the Designer and the shell it renders. This is the phase that runs on a PC today, and the one the phone build will package.

Working

  • Theme format 6: phone, desktop and tablet element sets in one .hui.
  • Loader that validates types and ranges, clamps loose values and refuses hostile or corrupt archives.
  • Atomic install with rollback — a theme that fails to load, or keeps crashing the shell, is replaced by the previous one.
  • Designer for Windows: live phone, desktop and tablet preview, saved out as a .hui.
  • Qt/QML shell: theme in, three surfaces out, clickable icons, app windows, working start menu, runtime surface switch.
  • Dock detection on Linux: USB and display state read from the system, surface chosen and recorded for the shell.
  • Test suites for both halves: 75 format and loader tests, plus click tests that drive the shell.

Next in this phase

  • First device build — package the shell for a supported phone and boot it.
  • Third-party app theming — an opt-in API and adapters so apps that are not ours follow the active theme.
  • The Workshop — install, switch and roll back themes from one app.
  • Dock detection on real hardware instead of mock devices.

Phase 2 · Physical board testing

From a window on a PC to a phone in hand

Not started

Flashing validated builds onto prototype boards and running the shell on the hardware it was sized for. This is where thermals, battery behaviour, touch input and the real docks stop being assumptions. Dock detection has only been tested against simulated USB and display state so far.

Phase 3 · Tooling and manufacturing

Enclosures, glass, and only then pre-orders

Not started

Case tooling, the thermal back glass and the docks. Pre-orders are not open, and will not open before there are physical boards running the software. Nothing on the hardware pages exists yet beyond design intent.

How it's checked

Claims on this site have tests behind them.

The parts marked working are the parts with suites that fail when they break — not features that were seen once and written down.

✓
Format and loader

75 tests cover valid themes, out-of-range values, missing files, wrong hashes and malformed archives. A bad theme is rejected, not rendered halfway.

✓
Interaction

The shell's click tests open an app from the phone grid and dock, toggle the desktop start menu, open an app window and close it again.

✓
Surface choice

Dock detection is tested with simulated device trees: cooling dock, laptop dock and tablet shell each select the right surface, in the right order of precedence.

✓
Screenshots on this site

Every render is a frame from the shell itself, captured from the running app — not a mockup drawn for the website.

What is not claimed: that IndeXOS boots on a phone, that any app runtime works, or that the hardware exists. Those are later phases, and the site will say so until they are done.

Get told when a phase moves.

Updates go out when something real changes — a device build booting, an app runtime working, a dock recognised on hardware.
